## 数据集合

- `players`：主键为 `stream`；必填字段 `stream, device, course, duration, wall_start, content_start, network`，当前 26 条。
- `heartbeats`：主键为 `heartbeat`；必填字段 `heartbeat, stream, wall, content`，当前 365 条。
- `probes`：主键为 `probe`；必填字段 `probe, stream, wall, inclusion_probability, delivered, stratum`，当前 52 条。
- `group_sessions`：主键为 `stream`；必填字段 `stream, min_people, max_people, roster`，当前 1 条。
- `courses`：主键为 `course`；必填字段 `course, topic, duration`，当前 3 条。
- `sampling`：主键为 `design`；必填字段 `design, stratum, probability`，当前 2 条。
- `contact_policy`：主键为 `policy`；必填字段 `policy`。`maximum_per_person` 为每人每轮可承受的个人提问次数，`maximum_per_group_session` 为每个集体课堂可承受的集体提问次数；两类机会分别记账，互不占用。

集合中的主键不得重复；schema 的 foreign 引用须指向已存在的记录。可空字段保留 null 的业务含义，不自动补零。

## 估计口径（版本 v1）

所有估计共用同一口径，调整抽样机会或改用集体播放只改变不确定性，不改变口径本身。

- 设备播放：单条流的确认秒数（相邻心跳间按标称间隔计入）与可行秒数（首末心跳全区间）；缺心跳区间为两者之差，不补满也不计零。首心跳之前与末心跳之后不计入。
- 个人可能接触：同一老人全部设备流（含集体签到）的墙钟并集；重叠设备与重复播放不重复计时。内容去重为各设备内容位置的并集。
- 回应支持的投入：仅使用真正执行的提问机会（delivered 且非跳过），按抽样机会倒数加权（Horvitz-Thompson）；未回应不视为没在听，只保留为不确定。区间取设计方差与平滑二项下限的较大者，避免小样本全回应时过度自信。已送达未回执记为 pending，不计入份额两端。
- 集体播放：到场人数只有签到范围；roster 成员的时段计入其个人并集，签到范围外人数以区间保留在课程层，不计入任何个人；集体回应无法对应到个人。
- 支持秒数 = 回应支持份额区间 × 对应暴露区间。个人部分用个人设备暴露，集体部分只乘未签到人数区间，避免重复计数。

这些估计用于课程与时段层面的证据比较，不能用于评价个人是否认真学习。

## 查询与材料

GET 查询使用 UTF-8 JSON，错误参数返回 400，不存在的接口返回 404。重复的单值参数视为无效。summary 与 HTTP 调用同一组只读计算，材料包含数据内容指纹和生成时间，便于核对输入。

- `/api/playback`：设备流播放统计，含确认/可行/未核实秒数与内容未播尾段。
- `/api/probes`：提问原始计数与真实执行情况（sampled/executed/not_executed/pending），有业务日志时附 workflow 执行汇总。
- `/api/engagement`：三层估计（设备播放、个人可能接触、回应支持的投入）及证据说明、使用限制。
- `/api/comparison`：课程比较，含暴露区间、支持份额与区间、证据缺口、口径说明；区间重叠时 ranking_supported 为 false。
- `/api/coverage`：下一轮覆盖安排。参数 `individual`、`group` 为两类机会预算（默认按剩余可承受次数）。分配由当前不确定性驱动：证据不足（已执行机会少于 4）的单元优先，其次区间最宽者。输出含每单元建议流与投放次数、投影区间、proposal_id 及投放回执核对（reconciliation）。

## 现有办理协作

sampling_plan.prepare 接受人工设备清单与计划抽样机会，可选 kind（individual/group，默认 individual）与 proposal（覆盖建议编号，便于核对）；集体计划只能面向集体流，个人计划不能投向集体流。probe_delivery.deliver 执行每人打扰上限与每场集体上限，可跳过重复设备，跳过记录原因（person_cap/group_session_cap），只有真正送达才算执行的机会。probe_receipts.record 保留真实回应，跳过的投放不能登记回应。

每个操作在本地业务日志的事务中更新；失败不提交半条办理记录。估计只消费真正执行的机会：未送达与跳过的机会列在 reconciliation 中，不进入回应分析，后续估计不会当作计划全部投放。接口传入业务标识，未知标识或不满足条件返回错误，不自动补建对象。
